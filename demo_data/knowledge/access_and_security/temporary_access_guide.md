# 临时系统权限申请与审批指南

> 文档属性：BizOrch虚构演示企业操作指南，仅用于本地项目演示。  
> 发布部门：企业IT服务部  
> 版本：2026.1

## 一、适用范围

本指南适用于员工因项目协作、短期支援、审计配合或岗位代理，需要在限定时间内访问CRM、ERP、项目协作平台等企业系统的场景。长期岗位权限应通过正式岗位权限流程维护，不应通过连续提交临时申请规避治理要求。

## 二、申请要求

申请人需要明确目标系统代码、角色代码、授权天数和业务理由。临时权限期限不得少于1天，不得超过90天；到期后的回收由企业权限平台负责，BizOrch第一版演示不实现定时回收。申请CRM客户只读权限时，应选择`CRM`系统和`read_only`角色，并说明对应客户项目或工作任务。

同一员工已经拥有相同系统和相同角色的有效权限时，不应重复授权。流程在生成方案前可以查询现有权限，审批通过后、真正执行前还必须再次查询，防止等待期间业务状态已经变化。

## 三、审批人检查要点

直属领导应核对申请人与业务任务的关系、目标角色是否符合最小权限、授权期限是否合理、业务理由是否可追溯。审批页面显示的操作版本、目标员工、系统、角色和期限必须与最终执行方案一致。审批人不得只依据聊天摘要或口头说明做决定。

驳回表示该申请已经完成处理但不会执行授权；批准后流程从原审批中断点恢复，重新执行确定性检查，再由Action Gateway调用企业系统。浏览器中的批准按钮只提交决定，不能直接写入企业权限系统。

## 四、异常处理

员工离职、账号停用、应用停用、角色已下线、审批版本过期或写后验证失败时，自动授权应停止。能够确认失败的操作可以按明确规则处理；结果未知的操作必须先查询核对，仍无法确认时转人工处理。
